# The Detekt convention plugin

Detekt is a build-wide quality convention, not a module-type convention. Add `<prefix>.detekt` only
when the user wants one shared policy across multiple modules; keep a single module's Detekt setup in
that module. Apply this add-on beside each consumer's existing module convention. It must not apply
or choose Android, JVM, or Kotlin Multiplatform plugins. The illustrative placeholders are
`<prefix>`, `<confirmed-version>`, `<matching-group>`, `<matching-plugin-id>`,
`<existing-module-convention>`, and `<selected-consumer>`; replace each from the survey or a
confirmed user choice.

## Step 1 — survey the policy and the Detekt major

Run `scripts/survey.sh`, then inspect the files it identifies. The survey already prints the root
build, catalog, module build files, and existing build-logic filenames; no Detekt-specific script is
needed. Read any existing Detekt plugin class and configuration file directly.

Before editing, establish all of these:

- the existing Detekt plugin id, version, Gradle artifact, imports, and rule-set artifacts;
- which modules should consume the policy;
- whether a root config and any baselines already exist.

For Detekt 2.x only, also survey source directories, excludes, reports, parallelism, correction
behavior, and optional rule sets. The canonical 1.23.x class in step 3 fixes those choices explicitly.

Follow the official documentation for the surveyed version. Detekt 1.x and 2.x are not source-
compatible:

| Detekt line | Gradle plugin id | Gradle artifact | task/extension packages | formatting rule set |
|---|---|---|---|---|
| 1.23.x | `io.gitlab.arturbosch.detekt` | `io.gitlab.arturbosch.detekt:detekt-gradle-plugin` | `io.gitlab.arturbosch.detekt.*` | `io.gitlab.arturbosch.detekt:detekt-formatting` |
| 2.x | `dev.detekt` | `dev.detekt:detekt-gradle-plugin` | `dev.detekt.gradle.*` | the matching 2.x ktlint-wrapper artifact from that version's docs |

Do not copy an id, coordinate, import, extension API, or rule-set artifact across that boundary.
Detekt 2.x may still be a prerelease in the build being edited, so preserve the surveyed line unless
the user separately asks for an upgrade. The canonical starting points are the versioned
[1.23.8 Gradle guide](https://detekt.dev/docs/1.23.8/gettingstarted/gradle/) and the
[current Gradle guide](https://detekt.dev/docs/gettingstarted/gradle/).

Now gate all edits on the config decision. If root `detekt.yml` exists, preserve it unchanged, ask no
config question, and continue to step 2. If it is absent, ask exactly one standalone, two-option
question for the surveyed Detekt line; this is a choice, not a policy checklist:

- **Detekt 1.23.x:** “Root `detekt.yml` is missing. Choose the bundled static 1.23 policy, which adds
  its legacy `detekt-formatting` artifact, or the complete defaults generated by Detekt 1.23.x.”
- **Detekt 2.x:** “Root `detekt.yml` is missing. The bundled 1.23 policy is incompatible. Choose
  complete defaults generated by this Detekt 2.x version, or provide/approve a 2.x policy.”

Wait for and record that one answer before modifying the catalog, build logic, consumers, or any
other target-build file.

## Step 2 — wire the catalog and the single classloader

Reuse existing aliases. Otherwise add one version, the external plugin, its Gradle artifact, and the
project's convention id. The coordinates below are illustrative placeholders: fill them from the
version selected in step 1.

```toml
[versions]
detekt = "<confirmed-version>"

[libraries]
detekt-gradle-plugin = { module = "<matching-group>:detekt-gradle-plugin", version.ref = "detekt" }

[plugins]
detekt = { id = "<matching-plugin-id>", version.ref = "detekt" }
<prefix>-detekt = { id = "<prefix>.detekt" }
```

Declare the external plugin once in the root build:

```kotlin
plugins {
    alias(libs.plugins.detekt) apply false
}
```

The convention class applies the external plugin by id, but that alone is enough only if it uses no
Detekt types. A useful convention configures `DetektExtension`, `Detekt`, or equivalent version-
specific types, so `build-logic/convention/build.gradle.kts` also needs the matching Gradle artifact
on its compile classpath:

```kotlin
dependencies {
    compileOnly(libs.detekt.gradle.plugin)
}
```

Keep it `compileOnly`. The root `apply false` declaration owns the runtime plugin classpath; together
these preserve the same single-classloader invariant as AGP and KGP.

Register the project convention in the existing `gradlePlugin` block. Use a plain, correctly spelled
registration name; only the id and implementation class are externally significant.

```kotlin
gradlePlugin {
    plugins {
        register("detekt") {
            id = libs.plugins.<prefix>.detekt.get().pluginId
            implementationClass = "DetektConventionPlugin"
        }
    }
}
```

For the canonical 1.23.x class, add the version-matched `detekt-formatting` library alias and
dependency. The static policy enables its legacy `formatting:` section, and the class installs the
artifact for either config choice. For 2.x, add only the rule-set artifact selected from that
version's official documentation. `detektPlugins` is opt-in; applying the Gradle plugin does not
install extra rule sets automatically.

When the target build already provides a `DependencyHandlerScope.detektPlugins(...)` extension,
import and reuse it:

```kotlin
dependencies {
    detektPlugins(libs.detekt.formatting)
}
```

If it does not exist, add the smallest helper alongside the build's existing dependency helpers —
for example in its existing `extensions/Project.kt` — as part of this Detekt setup:

```kotlin
fun DependencyHandlerScope.detektPlugins(module: Any) {
    add("detektPlugins", module)
}
```

Then import and use it through the same `dependencies { detektPlugins(libs.detekt.formatting) }`
call above. Do not build a helper hierarchy or add any further abstraction.

## Step 3 — create the version-matched convention

For Detekt 1.23.x, use this canonical class. Keep the local `extensions.libs` and
`extensions.detektPlugins` imports aligned with the existing helper package if the build uses a
different package name; all Detekt and Gradle imports below are required.

```kotlin
import extensions.detektPlugins
import extensions.libs
import io.gitlab.arturbosch.detekt.Detekt
import io.gitlab.arturbosch.detekt.extensions.DetektExtension
import org.gradle.api.Plugin
import org.gradle.api.Project
import org.gradle.kotlin.dsl.apply
import org.gradle.kotlin.dsl.configure
import org.gradle.kotlin.dsl.dependencies
import org.gradle.kotlin.dsl.withType

class DetektConventionPlugin : Plugin<Project> {
    override fun apply(target: Project) {
        with(target) {
            apply(plugin = libs.plugins.detekt.get().pluginId)

            extensions.configure<DetektExtension> {
                buildUponDefaultConfig = true
                toolVersion = libs.versions.detekt.get()
                config.setFrom(files("$rootDir/detekt.yml"))
                parallel = true
                autoCorrect = true
                source.setFrom(fileTree("src") {
                    include("**/*.kt")
                })
            }

            tasks.withType<Detekt>().configureEach {
                exclude(
                    "**/.gradle/**",
                    "**/.idea/**",
                    "**/build/**",
                    ".github/**",
                    "gradle/**",
                )
                reports {
                    html.required.set(true)
                }
            }

            dependencies {
                detektPlugins(libs.detekt.formatting)
            }
        }
    }
}
```

This template is deliberately 1.23.x-only. Its source input is intentionally target-derived: the
file tree covers only Kotlin files that exist beneath each consuming module's `src`, including
whichever KMP, JVM, Android, JS, or Wasm source sets that module actually has. If a project
deliberately keeps Kotlin outside `src`, add only those confirmed paths after surveying; do not add
speculative targets. The exclusions, HTML report, parallel mode, tool version, default-config
overlay, formatting dependency, and `autoCorrect = true` remain fixed. Because auto-correction is
enabled in the extension, ordinary `detekt` and `check` executions may modify source files.

For Detekt 2.x, do not reuse this class: follow the current official guide and the surveyed 2.x
plugin id, packages, APIs, source topology, rule-set artifact, reports, exclusions, and correction
policy. Do not infer `autoCorrect = true` or any other 1.23.x setting for 2.x.

## Step 4 — apply it to the selected consumers

Add the project convention alias beside each selected module's existing convention:

```kotlin
plugins {
    alias(libs.plugins.<prefix>.<existing-module-convention>)
    alias(libs.plugins.<prefix>.detekt)
}
```

Do not apply it blindly to every project. Build-logic, generated-only modules, and modules outside the
shared Kotlin policy may need no Detekt consumer plugin. Keep module-specific baselines or deliberate
source/report differences in the module unless the user confirms they are part of the shared policy.

## Step 5 — add the chosen new root config

If root `detekt.yml` already exists, leave it untouched and skip this step. Do not replace, regenerate,
or normalize an existing policy file.

Otherwise execute the choice recorded in step 1; do not ask again here.

For the **static 1.23 policy**, copy this skill's `assets/detekt-1.23.yml` to the target build root as
`detekt.yml` and track it with the rest of the setup. Use it only with Detekt 1.23.x and the matching
`io.gitlab.arturbosch.detekt:detekt-formatting` dependency from step 2. Do not adapt it into a static
2.x policy; use generated defaults or a user-provided/approved 2.x policy instead.

For **generated defaults**, first finish steps 1–4 so the convention points at root `detekt.yml` and
is applied to at least one selected consumer. A root `apply false` declaration resolves the plugin but
creates no `detektGenerateConfig` task by itself. Then run exactly one selected consumer's fully
qualified task:

```bash
./gradlew :<selected-consumer>:detektGenerateConfig
```

Do not run the unqualified `detektGenerateConfig` task across the build: every consumer is configured
to target the same root file, so multiple generator tasks would compete for one output. The generated
`detekt.yml` must be the complete default configuration produced by the surveyed Detekt version, not
a copied reference-project subset. Leave it as ordinary tracked source and include it with the setup.

The generator may omit configuration for optional third-party rule sets. If the user selected one,
such as formatting, append or enable only that version-matched rule-set section according to its
official documentation; preserve the rest of the generated default config.

Neither choice creates a baseline or authorizes unrelated policy changes. For Detekt 1.23.x,
auto-correction comes from the canonical class in step 3, not from the config choice.

## Verify

The Detekt Gradle plugin normally attaches analysis to `check`; do not add another dependency unless
the matching version's task graph or this build proves it is needed.

```bash
./gradlew --stop
./gradlew -p build-logic :convention:check
./gradlew help
./gradlew detekt
./gradlew check
```

Run `detekt` and `check` only after the chosen root config has been added, or after confirming the
existing root config was preserved. With the canonical 1.23.x class, both commands may modify source
because `autoCorrect = true`; inspect and report those changes with the findings. For 2.x, use the
correction behavior selected for that version rather than assuming the 1.23.x behavior. Do not silence
findings with broad excludes, a fabricated config, or a baseline that was not separately approved.
